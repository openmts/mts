# MTS 商用发布就绪度检视报告

## 结论

当前项目已经达到“单机嵌入式时序库商用候选版”的代码质量门槛，但尚不建议直接对外正式商用发布。主要阻塞是当前 Go 1.26.2 标准库存在 `govulncheck` 可达漏洞，且仓库缺少远端 CI 发布门禁和首个 release tag/API 兼容基线。

建议状态：`Release Candidate blocked`。升级 Go 工具链到 1.26.4 或更高版本并重跑门禁后，可进入正式发布前验收。

## 范围与边界

- 项目公开范围已限定为单机本地目录能力，明确不承诺分布式查询、分布式存储、外部元数据系统、SQL/InfluxQL/PromQL parser。证据：`README.md:3`、`README.md:5`。
- 稳定外部接口限定为 Go 根包 `github.com/openmts/mts` 和本地维护 CLI `cmd/mts-storage`，内部 HTTP 服务不作为外部稳定 API。证据：`README.md:7`。
- API 文档覆盖基础写入、Builder 查询、precision、typed batch、降采样、维护 CLI 和质量门禁。证据：`README.md:15`、`README.md:58`、`README.md:94`、`README.md:128`、`README.md:141`。

## 必须修复

### P0: Go 标准库可达漏洞阻塞正式发布

证据：

- `go.mod:3` 当前声明 `go 1.26.2`。
- 本机 `go version` 为 `go1.26.2 linux/amd64`。
- `govulncheck` 报告 3 个可达标准库漏洞，修复版本为 Go 1.26.4 或更高。

影响：

- 即使项目代码门禁通过，正式发布使用存在已知可达漏洞的标准库构建产物，会形成安全合规阻塞。
- 涉及 `internal/service/server.go` 中 HTTP server/listener 路径和标准库 x509/textproto/net 调用链。

处理建议：

1. 将开发和发布工具链升级到 Go 1.26.4 或更高兼容版本。
2. 更新 `go.mod` 的 `go` 版本声明和 `CONTRIBUTING.md:5` 的环境要求。
3. 重新执行：
   - `timeout 900s make ci`
   - `timeout 600s go run golang.org/x/vuln/cmd/govulncheck@latest ./...`
   - `timeout 60s git diff --check`

状态：未修复。

## 建议修改

### P1: 缺少远端 CI 配置，发布门禁目前依赖本地执行

证据：

- 仓库没有 `.github` 目录。
- 本地门禁脚本完整，见 `scripts/ci_gate.sh:16` 到 `scripts/ci_gate.sh:69`。

影响：

- 当前“商用门禁通过”依赖人工在本地执行，缺少 push/PR/release 级强制执行。
- 对外发布时，无法从仓库平台证明每个提交都通过同一套门禁。

处理建议：

- 增加 GitHub Actions 或当前远端平台等价 CI，至少执行 `make ci`、`govulncheck`、`git diff --check`。
- release tag 触发同一门禁，并保存测试/覆盖率/漏洞扫描摘要。

状态：未修复。

### P1: 尚无 release tag，无法执行 API 兼容性对比

证据：

- `git tag --list` 无输出。
- `CONTRIBUTING.md:24` 到 `CONTRIBUTING.md:32` 已说明首个 release tag 之后才执行 `apidiff`，当前无法对历史基线执行。

影响：

- 首次发布可以接受无历史基线，但发布后必须以 tag 固化 public API。
- 后续发布如果没有 `apidiff` 门禁，会增加破坏性 API 变更风险。

处理建议：

- 首次正式发布前打 `v0.x.0` 或 `v1.0.0` tag 前，确认 public API 冻结范围。
- 首个 tag 后把 `apidiff` 加入 release 前检查。

状态：未修复。

### P2: 性能门禁已有 smoke 和规模场景，但正式发布建议补固定基线

证据：

- Makefile 提供 `storage-100k`、`storage-1m`、`storage-10m`、`storage-matrix`、`bench-query`、`pprof-storage`。证据：`Makefile:141` 到 `Makefile:193`。
- CI regression smoke 覆盖 `storage_matrix` 和 `pprof/storage_engine`。证据：`scripts/ci_gate.sh:65`。
- 历史 benchmark 文档存在于 `docs/benchmarks/`。

影响：

- 当前具备性能验证工具和 smoke 保障，但正式发布说明中还缺少“本版本基线数据、测试机器规格、可接受阈值”的统一发布条目。

处理建议：

- 发布前跑一次标准 profile，例如 `storage-1m` 或文档中的 512MiB standard gate，并把结果写入 `docs/benchmarks/`。
- 将关键阈值加入 release checklist。

状态：未修复。

## 已满足项

- 功能范围清晰：单机嵌入式、本地目录、Builder/API 查询，边界已写入 README 和 CONTRIBUTING。
- 公开 API 可用性较完整：写入、typed batch、查询 Builder、precision、iterator、metadata、retention、compaction、downsample、维护 CLI 均有文档或测试覆盖。
- 质量门禁较强：`make ci` 包含格式化、全量测试、lint、逐包覆盖率、fault/scale/pprof smoke 和产物扫描。
- 覆盖率达标：商用门禁要求生产包 `>=90%`，本次 `make ci` 显示所有核心包达标。
- 运维文档存在：operations runbook 覆盖 metrics、health/ready、backup/restore、compaction、memory、slow query。证据：`docs/storage/operations-runbook.md:11`、`docs/storage/operations-runbook.md:30`、`docs/storage/operations-runbook.md:52`、`docs/storage/operations-runbook.md:59`。
- 安全默认较明确：pprof/admin 默认关闭，admin 需要 token 和 timeout。证据：`docs/storage/operations-runbook.md:5` 到 `docs/storage/operations-runbook.md:9`。
- admin 鉴权实现使用 token 检查和 constant-time compare。证据：`internal/service/admin.go:45`、`internal/service/admin.go:49`、`internal/service/admin.go:81` 到 `internal/service/admin.go:89`。

## 商用发布判定

按当前证据，结论如下：

- 代码功能与质量：达到商用候选水平。
- 文档与运维：达到单机嵌入式库的基本商用候选水平。
- 安全发布：未达标，Go 标准库可达漏洞阻塞。
- 发布治理：未完全达标，缺远端 CI 与首个 API 兼容基线。

最终判定：当前不应直接正式商用发布；修复 P0 后可进入发布候选验证，补齐 P1 后再做正式对外发布更稳妥。
