## 1. cmd/mts-dashboard/src/api/client.ts（169 行）

主要功能：基于 `fetch` 的 HTTP 客户端，封装 GET/POST/PUT/DELETE、Bearer Token 持久化、登录/登出、401/403 自动清理认证。

### Critical

- **Token 竞态/重复触发**（`client.ts:110-114`）：401/403 处理会调用 `clearAuth()` 后再触发 `onAuthFailed?.()`。当多个并发请求同时返回 401（典型场景：Dashboard 同时拉 4-5 个接口），`onAuthFailed` 会被同步多次触发，若 handler 内做 `router.push('/login')` 多次推入会污染历史栈；若 handler 内再次 `clearAuth` 也是冗余写 `localStorage`。**缺少去重 / 单次触发保护（如 `pendingAuthRedirect` 标志）。**
- **认证失败回调注册竞态**（`client.ts:67-71`）：`onAuthFailed` 为模块级单例，`setOnAuthFailed` 在多个组件 / hot-reload 下会被后注册者覆盖，无注销机制。组件卸载后未清理可能调用已销毁组件的回调。
- **Token 明文存储在 localStorage**（`client.ts:24-36`）：XSS 一旦发生即可窃取长期 token。`expires_at` 字段返回但前端从不校验过期，过期 token 仍会作为 `Authorization` 头发送直到服务端返回 401，期间用户体验差且产生无谓请求。
- **`apiLogout` 静默吞错**（`client.ts:163-168`）：捕获所有错误但未区分网络错误 vs 401/403。若因 401 进入此分支，`request` 内已 `clearAuth` 并触发 `onAuthFailed`，叠加 `apiLogout` 自身 `try/catch` 会让 401 → 登出回调再次触发，与上面竞态叠加。

### Important

- **`request<T>` 总是 `response.json()`**（`client.ts:123`）：成功响应体非 JSON（如 204 No Content、流式 NDJSON 文本）会抛 `SyntaxError` 从而把语义上的成功误判为失败。`QueryPage` 的 stream 模式因此被迫绕过 `client` 直接用 `fetch`（见 `QueryPage.vue:88-96`），旁路客户端 = 失去 401 处理。
- **`loadToken` 异常仅返回空字符串**（`client.ts:24-30`）：当 `localStorage` 被禁用（隐私模式 / Cookie 限制）时，模块初始化 `bearerToken = ''`，但后续 `saveToken` 同样静默失败，导致每次刷新后看似已登录（`isAuthenticated=!!getBearerToken()`）实则无 token，且无任何提示。
- **APIError.code 默认 `'internal'` 与 `status` 重复表达**（`client.ts:115`）：`response.statusText` 入 `message`，但 `code` 用固定 `'internal'`，调用方无法基于 code 区分网络层 vs 服务端错误。
- **无请求超时 / 无 AbortController 支持**（`client.ts:98-124`）：长查询（`/api/v1/data/query/stream`、`explain`）若服务端不返回，前端永久 pending；`apiGet`/`apiPost` 未暴露 `signal`，组件无法取消。
- **无请求重试 / 无指数退避**：对瞬时网络抖动不友好。

### Minor

- `client.ts:118` 的 `catch (_)` 命名用 `_` 良好，符合 AGENTS.md “无关紧要用 `_` 忽略”要求；但 `client.ts:35, 41, 55, 61` 的 `catch {}` 空块无注释标识忽略变量，建议统一为 `catch { /* 非关键 */ }`（已加注释，但仍建议显式 `_`）。
- `API_BASE = ''`（`client.ts:1`）写死空串，部署到非根路径（如 `/dashboard/`）需改源码，建议从 `import.meta.env.BASE_URL` 拼接。
- `apiPost` `body ? JSON.stringify(body) : undefined`（`client.ts:132`）：当 body 为 `false / 0 / ''` 这类假值时不会序列化，对需要显式发送空对象 `{}` 的接口会丢失 body。

### 安全

- Token 写 `localStorage`，无 `httpOnly` Cookie 方案，XSS 可读。
- 登录响应 `data.token.token`（`client.ts:149-154`）持久化前未校验非空，若服务端返回空 token 会写入空串并被 `request` 视为“无 token”跳过 Authorization，请求又 401，进入死循环登录。

### 错误处理缺陷

- `apiLogin` 抛 `APIClientError`，`useAuth.login` 转字符串返回；但 `APIClientError.code` 未透传到 UI（用户只看到 message，无法本地化“密码错误”vs“用户被禁用”）。
- 401 on `/api/v1/auth/login` 被显式排除（`client.ts:111`）正确；但 401 on `/api/v1/auth/password`（`UsersPage.vue:84`）会触发 `clearAuth` + 跳登录页，符合预期，但当前 token 仍可能是有效的——这是密码错误而非 token 失效，行为过激。

### 响应式布局

- 此文件无 UI。

### TypeScript

- `options.headers as Record<string, string>`（`client.ts:101`）强制断言，若调用方传 `Headers` 实例会出问题（当前未发生）。
- `APIError` 接口字段 `code/message` 与 `APIClientError` 重复定义，未共享。

## 2. cmd/mts-dashboard/src/composables/useAuth.ts（29 行）

主要功能：模块级 ref 单例式认证状态 + `login` / `logout`。

### Critical

- **`isAuthenticated` 初始值来自 `loadToken` 非空判断**（`useAuth.ts:4`，`client.ts:78`）：刷新页面后若 `localStorage` 有残留但服务端已过期/被撤销的 token，`isAuthenticated=true`，路由守卫放行进入主页，首个请求 401 → `clearAuth` → 跳登录。UX 上表现为“闪一下主页再跳登录”。**正确做法：刷新后立即触发一次 `/healthz` 或 `/api/v1/users/me` 校验 token 有效性，校验未通过直接置 `isAuthenticated=false`。**

### Important

- **`logout` 无竞态保护**（`useAuth.ts:21-26`）：`await apiLogout()` 期间用户可继续点击其他按钮触发请求；`apiLogout` 自身 401 时 `request` 已 `clearAuth`，再执行 `clearAuth()` 重复调用，最终 `onAuthFailed` 可能跳登录两次（与 `client.ts` 竞态叠加）。
- **`login` 成功后未 `await router.push` 失败处理**（在 `LoginPage.vue:27`，`useAuth.login` 本身无）：`login` 返回 `null` 表示成功，但用户已登录态切换与路由跳转之间无原子保证——若 `router.push` 失败（如目标路由不存在），用户会停在登录页但已登录。
- **`login` 异常未区分 `APIClientError` vs 网络错误**（`useAuth.ts:16-18`）：网络断开时返回 `'登录失败'`，与“密码错误”不可区分，UX 差且有误导。
- **`currentUser` 与 `client.ts` 的 `currentUserName` 双源**（`useAuth.ts:5` + `client.ts:88`）：`logout` 先 `clearAuth()` 置空 `currentUserName`，再置 `currentUser.value = ''` 为双写，二者顺序错乱时短暂不一致。

### Minor

- `useAuth.ts:2` 导入多个函数单行过长，可读性差。
- `login` 返回 `string | null`（错误字符串或 null）为非惯用模式，建议 `throw APIClientError` 或返回 `Result<T>`；当前模式让 `LoginPage.vue:24` 必须写 `if (err) error.value = err`，反直觉。

### 安全

- 无过期 token 主动校验（见上）。

## 3. cmd/mts-dashboard/src/router/index.ts（38 行）

主要功能：路由声明 + `beforeEach` 登录守卫。

### Critical

- **未鉴权用户直接访问 `/login` 已登录时未重定向**（`router/index.ts:31-36`）：守卫仅处理“非 Login 且未登录 → 跳 Login”，已登录用户再次访问 `/login` 仍显示登录页，可重复登录产生多个 token。
- **守卫未处理目标路由为 `DashboardLayout` 子路由但 `isAuthenticated=false` 之外的鉴权细节（角色）**：`users` / `config` / `operations` / `downsample` / `storage` 实际需 admin 权限，路由层无 meta 声明，**仅靠页面内 `isCurrentUserAdmin` computed 控制 UI 显隐**（`UsersPage.vue:192-200`），非 admin 直接访问 URL 不会被拦截，体验为先加载后 403 再被踢登录（见 `client.ts:111`）。

### Important

- **`beforeEach` 返回 `{ name: 'Login' }` 未携带 `redirect` query**（`router/index.ts:34`）：登录成功后 `LoginPage.vue:27` 直接 `router.push('/')`，丢失用户原本想去的路径（如分享链接 `/databases`），UX 不友好且易被误判为 bug。
- 无 404 兜底路由：访问未知路径进入 `DashboardLayout` 的空 `<RouterView />`，页面空白无提示。

### Minor

- 路由懒加载全部用动态 import，未配置 `manualChunks`，首屏所有页面可能合并为单 chunk；Vite 默认按动态 import 自动分块，影响有限。

### 安全

- 守卫依赖客户端 `isAuthenticated`，纯 UI 保护，**真实接口鉴权仍由后端保证**——此为前端正确前提。但需在 README/文档说明，避免误用为保护机制。

## 10. cmd/mts-dashboard/src/pages/UsersPage.vue（401 行）

主要功能：用户 CRUD、改密、数据库权限授予/撤销，按角色过滤显示。

### Critical

## 跨文件重点关注项汇总（按本次任务“特别关注”逐项回答）

### A. client.ts 的 token 存储和 401/403 处理是否有竞态条件

**有，且为 Critical。**
- 多并发请求同时 401 → `onAuthFailed` 同步多次触发（`client.ts:110-114`），无去重标志。
- `apiLogout` 内 401 时 `request` 已清理 + 触发回调，`useAuth.logout` 又显式 `clearAuth`，叠加 `useAuth.ts:21-26`。
- `onAuthFailed` 单例注册，组件卸载无注销（`client.ts:67-71`），可能调用已销毁组件逻辑。
- 修复建议：加 `pendingAuthRedirect` 标志；`apiLogout` 用独立 `fetch` 而非走 `request`；`onAuthFailed` 改为 WeakSet 多 handler。

### B. useAuth.ts 的 login/logout 是否正确处理所有边界情况

**未覆盖边界：**
- ✓ 空 token 响应（`useAuth.ts:11` 未校验 `data.token.token` 非空，前端会写入空串导致后续 401 死循环——Critical）。
- ✗ `login` 成功后未校验 `expires_at` 是否已过期。
- ✗ `logout` 期间多次点击无防抖。
- ✗ 网络错误与认证错误不可区分（`useAuth.ts:16-18`）。
- ✗ 刷新页面 token 过期场景未做主动校验 → 闪主页（`useAuth.ts:4` 初始值依据）。

### C. WritePage.vue 的行协议和 Prometheus 解析器是否有注入风险或解析错误

**存在解析错误（部分 Critical）：**
- 行协议转义未支持（`WritePage.vue:114-117, 150-182`）→ 含 `,` ` ` `=` 的 tag/field 被错切，静默数据错误。
- 纯整数被存为 float64（`WritePage.vue:134-135`）→ 大整数精度丢失。
- `lastIndexOf(' ')` 分 timestamp（line 169-180）→ 字段含未转义空格时 timestamp 被误判，时间被 `Date.now()` 覆盖。
- `parseInt` / `parseFloat` NaN 未校验（line 127, 132-135）→ `int64: null` / `float64: null` 静默写入。
- Prometheus 正则不支持 `+Inf/-Inf/NaN`（line 191）→ 这些样本静默跳过。
- Prometheus 标签 `\"` 转义未正确处理（line 216-219）。
- Prometheus 时间戳单位推断（`tsMs < 1e15`，line 229-231）→ 10 位秒级时间戳被当毫秒 ×1e6 偏移 1000 倍。
- 无注入风险（写入数据进入 JSON body，非 SQL/shell 拼接），但数据库/measurement/tag 字段无长度与字符白名单，依赖后端。

### D. 各页面的 null/undefined 检查是否完整

**不一致，多处风险：**
- ✓ `OverviewPage` `memorySnapshot`/`compactionStats` 用 `v-if` 守卫 OK。
- ✗ `DatabasesPage` 用 `!db.measurements.length` 替代 null 检查做幂等（`DatabasesPage.vue:58, 83`），空列表时失效。
- ✗ `DatabasesPage.formatDuration(rp.duration)` 假设 duration 非 0 且非负，未护。
- ✗ `QueryPage` `data.result?.stats` 用 `?.` OK（`QueryPage.vue:84`），但 `data.result?.columns as QueryResultRow[]` 强转无运行时 check。

- ✗ `DownsamplePage.getStatus(policy.name)!.completed_until_unix`（`DownsamplePage.vue:124`）非空断言，前有 `getStatus(...) ?` 守卫 OK，但 `completed_until_unix` 自身可能 0，`formatUnix(0)` 返回 `'-'`（line 88）OK。
- ✗ `WritePage` `fieldTypes.find(...)!` 非空断言（`WritePage.vue:88-93`）。

### E. 测量/数据库选择联动逻辑是否正确

**基本正确但有竞态：**

## 结论

MTS Dashboard 整体架构清晰、Tailwind 响应式基础扎实，但存在以下系统性问题需集中治理：

1. **认证流程存在竞态与边界缺失**（client.ts + useAuth.ts + router 联动）。
2. **写入解析器存在数据正确性 bug**（行协议整数精度、timestamp 解析、NaN）。

4. **错误处理普遍吞错**，难以前端定位；并发 `Promise.all` 对部分失败过严。
5. **缺乏前端测试与 lint 基础设施**，与 AGENTS.md 测试覆盖率要求冲突。
6. **2 个文件超 300 行硬上限**（UsersPage / WritePage），需拆分。

建议按上面 P0 → P1 顺序分迭代修复，P0 项应在下一个里程碑前完成。
