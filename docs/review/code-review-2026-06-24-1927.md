# MTS 用户管理模块检视报告

## 结论

检视前，项目没有完整的 public 用户管理模块；仅存在 `internal/queryservice` 的 tenant allowlist 鉴权，不满足外部商用 API 对用户 CRUD、DB 级授权和第三方权限系统对接的要求。

本轮已补齐接口化用户管理模块：public `UserManager` 接口、默认 `LocalUserManager`、用户增删改查、DB 级 `read/write/admin` 授权、Engine wrapper、默认持久化和 public e2e 均已落地。

## 范围与边界

- 范围：根包 `github.com/openmts/mts` 的 public 用户管理 API、默认本地实现、Engine 集成、public e2e 和文档。
- 权限粒度：当前仅细化到 database 级别。
- 非目标：密码、token、session、HTTP 登录、第三方权限系统实现、SQL/PromQL/InfluxQL parser。
- 集成策略：现有 `Write`/`Query` API 不默认拦截用户上下文；调用方在入口层显式调用 `CheckUserDatabasePermission`。

## 已修复问题

### P0: 缺少完整 public 用户管理接口

状态：已修复。

证据：

- `user_types.go` 定义 `UserManager`、`User`、`DatabaseGrant`、用户管理错误和 `DatabasePermission`。
- `local_user_manager.go` 实现默认本地用户 CRUD。
- `engine.go` 暴露 `CreateUser`、`UpdateUser`、`GetUser`、`ListUsers`、`DeleteUser`。

### P0: 缺少 DB 级权限管理

状态：已修复。

证据：

- `local_user_permissions.go` 实现授权、撤销、列表和校验。
- 权限集合为 `read`、`write`、`admin`，其中 `admin` 隐含 `read/write/admin`。
- 禁用用户和缺失授权均拒绝访问。

### P1: 缺少默认本地持久化和第三方注入边界

状态：已修复。

证据：

- `OpenLocalUserManager(dir)` 默认使用本地 `users.bin` 二进制 envelope。
- `Options.UserManager` 支持注入第三方实现。
- 注入第三方实现时不会创建默认本地 `users.bin`。
- `Engine.Close` 会关闭默认本地用户管理器。

### P1: 缺少公开 workflow、文档和覆盖率门禁

状态：已修复。

证据：

- `tests/e2e/public_api_workflow` 覆盖用户创建、授权、重启恢复和权限校验。
- `README.md`、`doc.go`、`llms.txt` 已补充用户与权限说明。
- `user_management_test.go`、`user_permissions_test.go`、`user_engine_test.go` 覆盖 CRUD、权限、持久化、Engine 默认和注入路径。

## 当前判定

- 用户管理模块：已达到当前单机版本的基本商用 API 要求。
- 第三方权限系统对接：已有 `UserManager` 接口化边界，可通过 `Options.UserManager` 注入。
- 默认实现：已有本地 `LocalUserManager`，支持用户 CRUD、DB 级权限管理和二进制持久化。
- 正式商用发布：仍需先升级 Go 工具链到 1.26.4 或更高并重新通过 `govulncheck`。
