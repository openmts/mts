# mts 跨平台能力检视报告

## 结论

mts 主体代码已具备 Windows、Linux、macOS 三个平台的编译能力。本次检视发现并修复了 Windows 下不可编译的 Unix-only `syscall.Statfs` 路径，同时把 RSS 采样和压测 RSS peak 指标拆分到平台适配文件，避免平台差异散落在通用代码中。

## 检视范围

- Go module 全量包：`go test ./...`
- 交叉编译目标：`linux/amd64`、`darwin/amd64`、`windows/amd64`
- 平台敏感 API：`syscall`、`/proc/self/status`、文件权限、路径拼接、文件同步、rename、压测工具 RSS 指标

## 问题清单

### P0: Windows 编译失败

- 状态：已修复
- 位置：`internal/engine/ports.go`
- 现象：通用文件直接引用 `syscall.Statfs_t` 和 `syscall.Statfs`，Windows 目标不存在这些 API。
- 修复：新增 `internal/engine/diskspace_unix.go` 和 `internal/engine/diskspace_windows.go`。Unix 使用 `syscall.Statfs`，Windows 使用 `kernel32.dll` 的 `GetDiskFreeSpaceExW`。
- 验证：`GOOS=windows GOARCH=amd64 go test ./... -run '^$' -exec=/bin/true` 通过。

### P1: RSS 采样 Linux-only

- 状态：已修复
- 位置：`internal/engine/memory_budget.go`
- 现象：通用代码直接读取 `/proc/self/status`。非 Linux 虽不编译失败，但 RSS 永远不可用且平台意图不明确。
- 修复：新增 `memory_rss_linux.go` 和 `memory_rss_other.go`。Linux 保留 `/proc` 采样，其他平台显式返回不可用并由 runtime heap fallback 保持快照有效。
- 验证：新增 `TestRuntimeStorageMemorySnapshotHasRuntimeMemory`。

### P1: 10M 压测工具 RSS peak 使用 Unix-only syscall

- 状态：已修复
- 位置：`tests/scale/storage_10m/main.go`
- 现象：通用文件直接调用 `syscall.Getrusage`，平台语义不一致。
- 修复：拆分为 `rss_linux.go`、`rss_darwin.go`、`rss_other.go`。Linux 按 KB 转 bytes，macOS 按 bytes 返回，Windows/其他平台返回 0。
- 验证：三平台交叉编译通过。

## 剩余注意点

- Windows 文件权限不会严格表达 POSIX 的 `0600/0700`，当前代码依赖 Go 标准库权限参数创建文件和目录；在 Windows 上它不会提供同等 ACL 语义，但不影响功能性运行。
- `tests/pprof/storage_engine` 仍使用 `/proc/self/status` 读取 RSS 指标；非 Linux 返回 0。该逻辑属于性能观测增强，不影响主存储路径和跨平台编译。
- 当前在 Linux 主机上完成三平台交叉编译验证，未在真实 Windows/macOS 主机执行端到端运行测试。真实平台运行仍建议在 CI 中补充 Windows/macOS runner。

## 验证命令

```bash
timeout 180s env GOOS=linux GOARCH=amd64 go test ./... -run '^$' -exec=/bin/true
timeout 180s env GOOS=darwin GOARCH=amd64 go test ./... -run '^$' -exec=/bin/true
timeout 180s env GOOS=windows GOARCH=amd64 go test ./... -run '^$' -exec=/bin/true
timeout 180s go test ./internal/engine -run 'TestDefaultFileOpsAvailableBytes|TestRuntimeStorageMemorySnapshotHasRuntimeMemory' -count=1
```
