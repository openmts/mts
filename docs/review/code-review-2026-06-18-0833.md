# 专项一到专项六闭环检视报告

## 检视范围

- 规格：`docs/superpowers/specs/2026-06-17-commercial-storage-special-projects.md`
- 计划：专项一到专项六对应的 reliability、memory、compaction、query、format、operations 计划文档
- 代码：`internal/engine`、`internal/service`、`internal/wal`、`tests/scale`、`tests/e2e`

## 结论

专项一到专项五从计划勾选、实现备注和现有测试入口看，未发现明确未闭环任务。专项六已经具备基础 metrics、health、ready、pprof、admin compact、scale gate 和 soak 报告，但对照 EARS 仍有 3 个完成度不足项，需要本轮补齐。

## 问题清单

### P1-1 Engine ready 缺少结构化运维检查

- 状态：已处理
- 影响专项：专项六
- 证据：`internal/service.Health` 已支持 `Checks []HealthCheck`，但 `internal/engine.HealthSnapshot` 仍只返回 `Healthy/Ready/Reasons`。这导致真实 Engine 不能按 WAL、Manifest、disk、compaction、memory、maintenance 输出结构化 ready 原因。
- 风险：生产 `/readyz` 只能输出自由文本 reason，自动化运维无法稳定判断是哪类资源或子系统导致非 ready。
- EARS：When `/readyz` 被调用时，系统应检查 WAL、Manifest、disk space、compaction backlog、memory budget、maintenance errors；When `/readyz` 非 ready 时，系统应返回结构化原因。
- 处理备注：`internal/engine.HealthSnapshot` 和 public `mts.HealthSnapshot` 已增加 `Checks []HealthCheck`，Engine 输出 `wal`、`manifest`、`disk`、`compaction`、`memory`、`maintenance` 六类 checks。

### P1-2 专项六生产指标细分不足

- 状态：已处理
- 影响专项：专项六
- 证据：当前指标已有 WAL、MemTable samples/bytes、SSTable parts/rows/blocks、query samples/parts、runtime heap/goroutine/fd，但缺少 MemTable series/field、SSTable data/index bytes 和 compression ratio、query duration/budget/cancel、retention deleted bytes/delete errors、runtime GC pause 等 EARS 要求字段。
- 风险：指标能看见主干状态，但不足以定位读放大、压缩收益、查询超预算、retention 删除异常和 GC pause。
- EARS：When Engine 打开时，系统应注册 WAL、MemTable、SSTable、Query、Compaction、Retention、Recovery、StorageMemory、Runtime 指标；When metrics 暴露时，系统应避免高基数字段标签。
- 处理备注：已补 MemTable series/field/columns、SSTable data/index/total bytes 与 compression ratio、query duration/budget/cancel、retention deleted bytes/delete errors、runtime GC pause 指标。

### P2-1 专项六计划文档提交备注不准确

- 状态：已处理
- 影响专项：专项六
- 证据：`docs/superpowers/plans/2026-06-18-storage-operations-commercial.md` 的 Task 6 Step 3 已打勾，但实现备注仍为“待提交”。
- 风险：后续审计专项闭环时会误判提交状态。
- EARS：When 计划、目标、约束、关键决策、进度变化时，应同步更新相关文档。
- 处理备注：专项六原计划 Task 6 Step 3 已更新为提交哈希 `9b950af`。

## EARS 执行清单

- When Engine 生成 `HealthSnapshot` 时，系统应输出 `wal`、`manifest`、`disk`、`compaction`、`memory`、`maintenance` 六类低基数字段 checks。
- When 任一 ready check 失败时，系统应将 `Ready=false`，并在 check reason 和 snapshot reasons 中输出结构化原因。
- When Engine 暴露 metrics 时，系统应输出 MemTable series count、field count 和 flush trigger count。
- When Engine 暴露 SSTable metrics 时，系统应输出 data bytes、index bytes、total bytes 和 compression ratio。
- When 查询完成或失败时，系统应记录 query duration、budget errors、cancellations，并通过 metrics 暴露。
- When retention 删除 shard/part 时，系统应累计 deleted bytes、expired parts、delete errors。
- When runtime metrics 被采集时，系统应暴露 GC pause total。
- When 专项计划已提交时，系统应更新计划文档中的提交备注，避免“待提交”残留。
