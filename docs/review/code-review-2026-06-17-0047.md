# 存储层待优化项确认报告

时间：2026-06-17 00:47

## 结论

当前计划文档中的明确任务已全部勾选完成，包括 Phase 12-18、hotpath allocation、P1 performance 和 single-format。未发现 `internal` 与 `tests` 中仍残留的核心版本兼容符号，例如 `recordVersion`、`batchVersion`、`tombstoneVersion`、`partFormatVersion`、`FormatVersion`、`valueEncodingV*`、`decodeBatchV*`。

仍建议继续实施的优化项有 5 类，其中 3 类属于性能热路径深化，2 类属于性能治理与文档清理。它们不是已承诺任务的遗漏，而是当前实现继续压低 RSS、alloc_space、CPU 和观测成本的下一轮优化空间。

## 仍建议实施的优化项

### P1：SSTable indexed/plain page 与 compressed page 进一步 streaming

现状：
- aligned plain page 已经走直接填充路径：`readAlignedSamples` 先创建目标 samples，再由 `fillAligned*Values` 原地填值。
- indexed plain page 仍会分配 `[]int64`、`[]uint64` 和最终 `[]VersionedSample`。
- compressed page plain codec 仍会通过 `readValues` 分配 `[]FieldValue`。

证据：
- `readIndexedTimeRefs` 分配 `[]int64`。
- `readWriteSeqs` 分配 `[]uint64`。
- `readSamples` 再分配 `[]VersionedSample`。
- `readValues` / `readFloatValues` / `readBoolValues` 等会分配 typed value slice。

参考：
- `internal/sstable/encoding.go:136`
- `internal/sstable/encoding.go:561`
- `internal/sstable/encoding.go:605`
- `internal/sstable/encoding.go:681`
- `internal/sstable/encoding.go:617`

建议：
- 为 indexed plain page 增加直接 append decoder，避免 timestamps/writeSeqs/samples 三段同时驻留。
- 为 compressed page 的 plain codec 增加 typed value streaming reader，避免 `[]FieldValue` 中间层。
- bool 路径继续按 bit 直接填充，避免 `[]bool` 或 `[]FieldValue`。

优先级：P1。

### P1：Catalog 多 tag series key 分配优化

现状：
- 0/1 tag 有快路径。
- 多 tag 仍会分配 keys、排序、构造 parts，并 `strings.Join`。

证据：
- `seriesKey` 多 tag 路径使用 `sort.Strings(keys)` 和 `strings.Join(parts, "\xff")`。
- resolve 热路径仍调用 `seriesKey(measurement, tags)`。

参考：
- `internal/catalog/key.go:8`
- `internal/catalog/key.go:23`
- `internal/catalog/key.go:27`
- `internal/catalog/resolve.go:54`

建议：
- 引入 batch-local canonical tag key scratch，减少每点分配。
- 或增加 tag-set fingerprint / intern cache，降低重复 tag set 的排序和拼接成本。

优先级：P1。

### P2：MemTable 查询避免 clone 整个 tableData

现状：
- `MemTable.Query` 调用 `Snapshot()`。
- `Snapshot()` 仍通过 `cloneData(m.data)` 复制整个 tableData。
- flush 路径已使用 `SnapshotAndReset` 和 table map 复用，但查询路径仍为一致性做全量 clone。

证据：
- `MemTable.Snapshot` 返回 clone。
- `MemTable.Query` 直接 `return m.Snapshot().Query(query)`。

参考：
- `internal/memtable/memtable.go:99`
- `internal/memtable/memtable.go:109`
- `internal/memtable/memtable.go:434`

建议：
- 增加 RLock 下只读 query iterator，查询只 materialize 命中列。
- 或引入不可变 column snapshot 视图，避免复制整个 tableData。

优先级：P2。

### P2：Value page index 单遍/两遍自适应策略

现状：
- 当前两遍扫描降低对象分配，是低内存路径。
- 对宽范围查询或 pageCount 很大的场景，两遍扫描会增加 CPU。

证据：
- `readValuePagesFromIndexPayload` 先调用 `matchingValuePageIndexHeader`，随后重新创建 reader 再扫描 page refs。

参考：
- `internal/sstable/read.go:319`
- `internal/sstable/read.go:333`
- `internal/sstable/read.go:360`

建议：
- 保留窄查询两遍扫描。
- 对全量或高命中率查询切到单遍读取，并使用受限 scratch 复用。

优先级：P2。

### P3：pprof 工具运行指标继续补齐

现状：
- 当前 pprof 工具输出 `sstable_count`、`data_dir_bytes`、`heap_alloc_bytes`、`heap_sys_bytes`。
- 还未输出 GC 次数、GC pause、TotalAlloc、Mallocs/Frees、RSS/VmHWM。

证据：
- `collectRunMetrics` 只读取 `runtime.MemStats.HeapAlloc` 和 `HeapSys`。
- 未发现 `NumGC`、`PauseTotalNs`、`TotalAlloc`、`Mallocs`、`Frees`、`VmRSS`、`VmHWM` 输出。

参考：
- `tests/pprof/storage_engine/main.go:104`
- `tests/pprof/storage_engine/main.go:261`
- `tests/pprof/storage_engine/main.go:291`

建议：
- 增加 `NumGC`、`PauseTotalNs`、`TotalAlloc`、`Mallocs/Frees`。
- Linux 下读取 `/proc/self/status` 输出 `VmRSS` 与 `VmHWM`。
- 固定输出字段便于后续 benchmark gate 自动对比。

优先级：P3。
