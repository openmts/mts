## 2. EARS 明细

### EARS-D1-01 查询默认保护
**状态：已处理**  
当客户端发起查询且未设置 `Limit`/`Budget` 时，系统应当注入可配置默认保护（`QueryProtection.DefaultMaxSamples` 等）。

### EARS-D1-02 MemTable 乱序降载
**状态：已处理**  
当乱序占比超过阈值时，系统应当更积极 flush。

### EARS-D1-03 超大文件拆分
**状态：已处理（阶段性）**  
memtable/wal 已拆分；shard/lifecycle 等后续继续。

### EARS-D2-01 可校准查询代价
**EARS：** 当 `BuildQueryPlan` / `QueryWithExplain` 返回 cost 时，`EstimatedSamples` 应结合匹配 part 的时间窗与 `RowsCount` 校准，并暴露 `MatchedParts`/`EstimatedPartRows`。  
**状态：已处理**  
- `Shard.estimateQueryPartStats` + `proportionalPartRows`  
- `estimateQuerySamples` 优先 part rows  
- public `QueryExplain`/`QueryCost` 同步暴露 part 统计

### EARS-D2-02 SSTable block fuzz
**EARS：** 关键 block 编解码应具备 round-trip 与 CRC 破坏拒绝的 fuzz/稳健性测试。  
**状态：已处理**  
- `internal/sstable/block_fuzz_test.go`：`FuzzBlockRoundTrip` / `FuzzBlockCorruptCRCRejected`

### EARS-D2-03 维护并发配额
**EARS：** compact 与 downsample 应有可配置全局并发上限，避免后台任务饿死前台。  
**状态：已处理**  
- `MaxConcurrentCompaction`（默认 1）  
- `compactionScheduler` 强制并发上限 + `concurrency_limit` skip  
- metrics：`mts_maintenance_compaction_max_concurrent`

### EARS-D2-04 协议 handler 共享
**EARS：** 同一 operation 鉴权+业务核心应在 runtime/registry 层共享。  
**状态：已处理**（P2-04 已落地 `operation_registry`，本轮确认无弱实现遗留）

### EARS-D3-01 Nightly 门禁
**EARS：** 热路径变更后 Nightly 应覆盖 fault/soak/scale/bench。  
**状态：已处理**（文档固化见 `docs/ops/nightly-gates.md`）

### EARS-D3-02 兼容矩阵
**EARS：** 发布文档应含 API/format 兼容矩阵。  
**状态：已处理**（`docs/compatibility.md` + `CHANGELOG.md` 扩展）

### EARS-D3-03 删除回收可观测
**EARS：** tombstone 物理回收应可观测。  
**状态：已处理**  
- gauge `mts_tombstones_pending`  
- 既有 `mts_compaction_dropped_rows_total` / `mts_compaction_safe_delete_parts_total`  
- 文档：`docs/ops/delete-reclaim.md`

### EARS-D3-04 无限扫描策略与告警
**EARS：** 生产配置应说明默认 budget/limit 与关键 metrics 告警。  
**状态：已处理**（`docs/ops/query-protection.md`）

### EARS-P3-01 远期存储形态
**状态：已处理（不含对象存储）**
