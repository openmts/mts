# MTS 用例完整性检视报告

## 范围

- 根包 `github.com/openmts/mts` 对外 API。
- 本地维护 CLI `cmd/mts-storage`。
- `tests/e2e`、`tests/fault`、`tests/scale`、`tests/pprof` 与 `internal/bench`。

## 结论

当前用例已经覆盖核心存储链路，但尚不能认定为完全齐全。主要缺口集中在外部用户视角的公开 API 闭环和读路径性能基准。

## 覆盖现状

- 已覆盖：点写入、基础查询、WAL 恢复、retention、compaction、读放大、format governance、降采样、故障矩阵、scale workload、pprof workload。
- 已覆盖：CLI check、repair、migrate、snapshot、restore 的单元级命令入口。
- 已覆盖：写入性能基准 `BenchmarkEngineWriteBatch` 与 `BenchmarkEngineWriteWideBatch`。

## 问题清单

### P1：缺少公开 typed batch + Builder + 迭代器跨重启端测

状态：已修复。

影响：README 推荐外部用户使用 `DefaultOptions`、`WriteTypedBatch`、Builder、`QueryRowIterator`、`QueryColumnIterator`，但现有端测没有把这些公开 API 串成跨重启闭环。公共转换层、元数据列表和迭代器行为若回归，可能只被内部包测试覆盖，外部 API 使用方式缺少直接保护。

验收：

- When 外部用户使用 `DefaultOptions` 打开本地目录时，系统应接受有效配置并创建可重启的本地存储。
- When 外部用户用 `WriteTypedBatch` 写入多字段 typed 数据并重启时，系统应通过 Builder 构造的 `QueryRowIterator` 和 `QueryColumnIterator` 返回正确结果。
- When 外部用户读取元数据时，系统应能列出 measurement、field schema 和 series。

### P1：缺少查询迭代器读路径性能基准

状态：已修复。

影响：当前 `internal/bench` 只覆盖写入路径。README 明确建议生产路径优先使用迭代器，但缺少 Row/Column iterator 的读性能用例，无法在性能回归时快速定位读路径开销变化。

验收：

- When 执行 benchmark gate 时，系统应同时运行写入和查询迭代器性能基准。
- When 读路径基准运行时，系统应遍历完整结果并校验行数或样本数，避免空跑。

## 非缺口说明

- 分布式查询、分布式存储、外部元数据系统、SQL/InfluxQL/PromQL parser 不属于当前项目边界。
- `internal/service` HTTP 查询和服务端点当前不作为外部稳定 API；已有 `service_ops` e2e 作为内部运维行为验证即可。
