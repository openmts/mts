# 专项一可靠性故障矩阵闭环检视

## 检视范围

- 计划文档：`docs/superpowers/plans/2026-06-17-storage-reliability-fault-matrix.md`
- 文件系统故障语义：`internal/storagefs`、`internal/faultinject`
- 恢复审计：`internal/engine/recovery_audit.go`、`internal/engine/shard.go`
- Flush / Compaction 原子性：`internal/engine/shard.go`、`internal/engine/lifecycle.go`
- WAL 故障矩阵：`internal/wal`、`internal/engine/wal_fault_test.go`
- fault matrix：`tests/fault/storage_fault_matrix`

## 结论

专项一原实现大部分闭环，但检视发现 2 个缺口：

1. `sstable.WritePartWithOptions` 自身失败时会残留未提交 part 目录。
2. fault matrix 声明覆盖 `PartWriter`、`Retention`，但缺少对应 case。

本轮已全部补齐，并补充了恢复审计临时 Manifest 文件清理测试。

## 问题清单

### 1. WritePart 半成品目录残留

- 严重程度：必须修复
- 状态：已修复
- 影响：如果 `WritePartWithOptions` 在数据块、索引、metadata、strings 写入或编码阶段失败，未提交 part 目录可能残留，后续依赖恢复审计清理，不能满足“失败路径即时清理”的原子性要求。
- 修复：`WritePartWithOptions` 在 `MkdirAll(partPath)` 成功后增加失败清理 guard，成功提交前任一错误都会 `RemoveAll(partPath)`。
- 测试：新增 `internal/sstable/atomic_write_test.go`，覆盖写入失败和编码失败两类路径。

### 2. fault matrix 缺少 PartWriter 和 Retention case

- 严重程度：必须修复
- 状态：已修复
- 影响：Task 5 要求覆盖 WAL、Manifest、PartWriter、FileOps、Compaction、Retention，原矩阵缺少 `PartWriter` 和 `Retention` 的失败路径。
- 修复：新增 `partwriter-write-failure` 和 `retention-remove-failure` case；schema 测试显式校验这些 case 必须存在。
- 测试：`TestRunMatrixReportSchema` 已覆盖报告字段和新增 case。

### 3. 临时 Manifest 清理缺少专门测试

- 严重程度：建议修改
- 状态：已修复
- 影响：实现已清理 `.tmp-*` 临时文件，但缺少回归测试保护。
- 修复：新增 `TestOpenShardRecordsMaintenanceIssueForRemovedTempManifestFile`。
